# Changelog

## Unreleased

### After upgrading

- Every browser is signed out once and signs in again. The sign-in cookie is now `__Host-kamosu_session`, which a page on another subdomain of the same domain can neither set nor replace, and the old `kamosu_session` is no longer read. [#368]
- A proxy in front of Kamosu must pass the `Host` header on unchanged, as Caddy and Traefik do by default and nginx does with `proxy_set_header Host $host;`, or the public address must be set. Otherwise every request a browser makes to change something is refused as coming from another site. Kamosu also speaks HTTP/1.1 only, so a proxy told to speak HTTP/2 to it in the clear must speak HTTP/1.1 instead. [#368]
- The model provider's key moves from the agent beside a Runner to the Runner. Put it in the Runner's settings as `KAMOSU_RUNNER_MODEL_KEY`, with the provider's API address as `KAMOSU_RUNNER_MODEL_ADDRESS`, and take `KAMOSU_AGENT_API_KEY`, or the provider's own variable, out of the agent's. Beside the published agent image, the Runner also needs `KAMOSU_RUNNER_MODEL_SOCKET` and a second socket volume shared with the agent, and the agent belongs behind the new fence, as the Compose file in `docs/runner.md` shows. Until the key moves, the agent works as before, and the Runner's log and the agent's say to move it. [#372]
- An Operator presses "Read every line again" on the Operator page once, so English lines already read with a thousands comma, such as `1,020 g`, are read again as a thousand and twenty grams. A Reading somebody set by hand is left alone. [#383]
- Every Access Key an Operator already holds still acts as Operator. Revoke any whose agent does not look after the instance, and mint it again as an ordinary key. `list_access_keys` says which keys act as Operator. [#369]

### Added

- `KAMOSU_DEMO_ERASES_LIBRARY_DAILY=true` turns an instance into a public demo. When it starts, it replaces the library with its own Sample Library of cooks, recipes and their history, and it puts that back every day at 04:00 UTC with every date moved forward, so a recipe's history always reads as recent. Visitors arrive signed in, with no password, as the Sample Library's Operator, Camille, and every screen opens, but only cooking, the Shopping List and signing out save. A visitor's cooking and shopping go at the next cleaning, and a page they hold open keeps working through it. A restart builds the library again, which signs every visitor in afresh and gives each recipe a new address. Everything else is refused at the moment of saving, at both Doors and on every upload, sign-in and Backup route, with the reason `demo`. A photograph taken while cooking shows where it would go, says the demo won't keep it, and disappears; the cooking's notes are kept. A demo takes no Backups. A visitor's own agent can read the library at the MCP door with the demo's read-only Access Key, which stays the same from one day to the next. No model runs in a demo, so the agent is shown at work on four ready examples: a handwritten card, a pasted blog post, a magazine page as a PDF and a YouTube video, offered under *Watch it read an example* in the +. Picking one plays its tracker through Sent, Waiting and Reading in a few seconds, saying a real read takes minutes, then shows the Report the agent left and the recipe it made, and writes nothing. A visitor's own photo, PDF, text or video link is refused with a button to the examples, and the demo says its agent has just asked for work. The demo says it is one: a welcome card at the top of Home says who the visitor is, what saves, when the library goes back, and the MCP address and read-only key to give their own AI (which `instance_status` now names in a demo), until they put it away; no screen offers to keep the library or Kamosu on the visitor's phone, and nothing is copied there unless they ask in Settings; a strip at the foot of every screen leads to it again and to installing Kamosu; and every refused save says, in the visitor's language and where it was asked, that only cooking and the shopping list are saved there. Leave the variable unset on any Kamosu whose library you want to keep: its first start as a demo erases it. [#403] [#404] [#406] [#407] [#426]
- A demo can count its visits with Umami: set `KAMOSU_DEMO_UMAMI_SCRIPT` to the script's address and `KAMOSU_DEMO_UMAMI_WEBSITE_ID` to the website's id. Its pages then load that script, their security policy lets that one address through, and `instance_status` names the script. Kamosu sets no cookie for it and asks no consent, since Umami needs neither. A Kamosu that is not a demo ignores both settings and still sends nothing anywhere. [#408]
- A person can log in with a passkey: their device's face, fingerprint or screen lock, or a phone held nearby. *Log in with a passkey* sits under the password, and Settings › Account lists each passkey, adds one after asking for the password, renames and removes them. Passkeys work only where the public address is an `https://` name, and only at that address; the Operator's address setting says how many would stop working at a new one. Agents can list and remove passkeys but not add one. [#370]
- A person can change their own password from Settings › Account, with the current one. Signing out their other devices is ticked to start with, ending their Access Keys is offered too, and their passkeys keep working. Before, only an Operator's recovery link or `kamosu recover` could. [#370]
- A Runner given the model provider's key relays its agent's model requests, so the agent never holds the key and a page that tricks it has none to send away. For each Job it opens a relay for that Job's agent alone, on the loopback for an agent command or at a socket for an agent in a container of its own, and hands the agent its address and a stand-in key in `job.json`, as `model_relay`. The relay puts the real key where the agent put the stand-in, in `Authorization`, `x-api-key` or `x-goog-api-key`, sends the request to the one address the Runner was given, under the same path, and streams the answer back. It refuses any other key, and closes when the Job ends. The published agent image sends opencode through it. [#372]
- The published agent image can be started as a fence, `/opt/kamosu-agent/fence`, whose network the agent's container shares. It lets the agent reach the internet and Kamosu's address, refuses the host, the LAN and every other private address, and keeps no root and no capability once its rules are set. [#372]
- Kamosu keeps a Security Record for 90 days, in Settings › Security record. Each person sees their own sign-ins and how each was made, wrong passwords at their name counted as one line per run, passkeys, password changes, Access Keys and Sessions ended. An Operator also sees the instance's: the House Notes and the public address changed, who was made an Operator or stood down, accounts disabled or deleted, Operator keys, Runner Keys, Backups fetched, and a crowd of sign-ins refused at once, each saying who did it through which Session or key. Agents read both with `list_security_record` and `list_instance_security_record`. Before, nothing recorded any of it. [#371]
- Each of those events is also one line on standard output, starting `kamosu-security`, in a fixed format a log watcher can match: `docs/security-record.md` describes it. It names Sessions and keys, never an address, a password or a Secret, and Kamosu sends it nowhere. [#371]
- Settings opens with *Import from another app*, a page of its own where the export file of the app you used before is dropped or picked, and Kamosu works out from what is inside it which app made it. It reads Mealie's recipe export and an administrator's backup, Paprika's, Tandoor's, KitchenOwl's and Crouton's, which moved here from This instance, and the page lists each app it reads and where that app keeps its export. From Mealie, a line that points at another recipe arrives as a Component of it, the other recipe arriving too where the export left it out, a picture placed in a step becomes that step's photo, tools become an Equipment line in the note, and a total time, a time Kamosu cannot read and nutrition beyond calories each go into the note as a line of their own, so a Mealie recipe imported before is offered once, with those lines, on the next import. A Mealie backup brings each recipe as the export does, and each "I Made This" as a finished cooking in the diary of whoever imports it, dated as in Mealie, with its message and photo and starting "Cooked by" and the cook's name, whoever cooked it. A backup holding several households asks which is yours and brings its recipes alone, a backup imported after the export adds the cookings to the recipes already there without shelving any twice, no cooking arrives twice, and the backup's passwords and tokens are never read. The Report counts each cook's ratings and favourites, and the meal plan's entries on a recipe's timeline, which say it was planned rather than cooked. From Paprika, each line of the ingredients arrives as an Ingredient Line and each line of the directions as a step, as written, the photo inside the file is kept, and a recipe whose only photo is a web address has it downloaded, the Report listing the address of any that could not be. A total time, a time Kamosu cannot read or reads only in part, servings with no count or the upper end of a range, the difficulty and the nutrition each go into the note as a line of their own, the nutrition as Paprika wrote it, so a Paprika recipe imported before is offered once, with those lines, on the next import. From Tandoor, which keeps no written line, each line is written out from its amount, unit, food and note as a cook writes it, the ingredients of every step come together in one list with each named step and each header row as a Section, a step's own time becomes the last line of its text, and nutrition beyond calories goes into the note. From Nextcloud Cookbook, RecipeSage, Recipya, CookCLI and Bar Assistant, which write recipes in the format web pages carry, and from Tandoor's Recipe Sage export, each recipe arrives as a web link's does, its keywords, categories and cuisines as Tags and its description and notes as the note, a photo beside it in the file or written into it kept, and one at a web address downloaded. What no field holds goes into the note as a line of its own: a total time, a time Kamosu cannot read, the equipment, the method, nutrition beyond calories, a video and the photo's credit. From Bar Assistant's own JSON Schema export, its default, a cocktail also keeps its garnish, its glass, and an ingredient's range, note and substitutes, and whether it is optional. From KitchenOwl's household export, the steps are read out of the recipe's description, each item of a list a step and the paragraphs around it the note, or each line a step where it holds no list, each line is the item's amount and name together, optional items come last under a Section of their own, and the total time goes into the note; KitchenOwl's export holds no photo, and the Report says so, counting the shopping lists, items and expenses it kept too. A recipe in it has no id, so it is known by its household's name and its own, and one renamed in KitchenOwl between two imports, or whose household was renamed, arrives twice. A file it does not recognise, or an app's export in a shape Kamosu was not tested with, is turned away on the page with nothing imported, saying which apps it reads, where to ask for another, and the ways one recipe at a time comes in. The Import Report counts what stayed behind in the old app in a section of its own, so it can be checked before the app is deleted. Crouton's nutrition text, which Kamosu does not read, is counted there too, where before it went unmentioned. Agents import the same way with `import_from_another_app`, which answers `which_household` for a backup of several households, and `import_crouton` works as before. [#412] [#413] [#414] [#415] [#416] [#417] [#418] [#434]
- Recipes can be narrowed by how they were cooked: *Never cooked*, *Not rated*, or a rating, *Again*, *Tweak it* or *No*, several at once. It reads everyone you cook with, and only your own cookings once *Cooked or written by me* is ticked, when *Never cooked* means every recipe on the shelf you have not cooked yourself. Where two cooks rated a recipe differently, it shows under both words. Agents ask for the same with `cooking` on `search_recipes`. [#445]
- An agent can correct which ingredients a step uses with `set_step_uses`, for a step Kamosu reads wrong, and `get_recipe` says which steps were corrected, in a new field, `by_hand`. A correction stays through later saves while the step and those ingredients stay word for word the same. [#439]

### Changed

- The Recipes screen's filters sit behind one row of buttons under the search box, Cookbooks, Kitchens, Cooking and Tags, each opening its list. A button names what it holds. Before, each group was a line of chips of its own, and with several they stood between the search box and the recipes. [#445]
- An Access Key an Operator mints acts as an ordinary Person unless it is minted as an Operator key, with `operator: true` on `mint_access_key`, which only an Operator signed in can do. Before, every key an Operator minted carried all of an Operator's powers, so any agent an Operator handed a key to could rewrite the House Notes every later Job reads. `mint_access_key` and `list_access_keys` answer which keys are Operator keys, in a new field, `operator`. An Operator key stops acting as Operator once its Person stops being one, and stays an ordinary key if they become Operator again. [#369]
- In Settings, an Operator creating an Access Key chooses whether it acts as them as a cook, which is the default, or as Operator too, and choosing Operator says what that hands an agent. A Person who is no Operator sees no choice. The key list marks an Operator key "Acts as Operator". [#369]
- A form that sets a password, on the first start, an Invite or a recovery link, asks for it twice, and says so when the two differ. [#369]
- *Sign out* stands at the foot of the Settings menu, under who is signed in, on the phone and on a wide screen. Before, it was a button on this device's row of the Sessions list, in Settings › Account. Both ask first, saying the recipes kept for offline use leave the device, and offline the button waits for the server. [#380]
- An Operation sent without `Content-Type: application/json` is refused. It used to run with an empty input. A request to an Operation, a sign-in or an upload that comes from a page on another address is refused too, where only `SameSite` kept one out, which a page on a sibling subdomain gets past. Agents, curl and the Runner send no `Origin` and are answered as before. [#368]
- Every answer also tells the browser to deny what Kamosu never asks for, such as the microphone and location, to keep its pages out of reach of windows another site opened, and to let no other site load its answers, except what a Share Link hands to anyone. An answer sent to an `https://` public address also tells the browser to come back only over HTTPS for a year. [#368]

### Fixed

- Setting a new password with a recovery link signs out every device and ends every Access Key the account held, so whoever had the old password is shut out. Before, they all kept working. The recovery page says so before the password is set, and the answer says how many in `ended_sessions` and `ended_access_keys`. It also ends every Runner Key the account minted, which the Security Record and `ended_runner_keys` count. Kamosu did not record who minted a Runner Key before this version, so an Operator's recovery ends every Runner Key minted earlier too, and the Runner needs a new one. [#369] [#378]
- A read-only Access Key can no longer fetch a Backup, which holds every password and Secret hash on the instance. [#369]
- A request with no Credential carries at most 64 KB, and is refused before its body is read when it says it carries more. Before, anyone could make Kamosu hold 40 MB per request in memory. A Credential that names nobody is answered before its body is read at all. A member's request keeps the 40 MB a phone's photograph needs. [#368]
- Kamosu lets go of a slow sender: a connection that takes more than 20 seconds to send a request's headers, or sits idle that long between two, a request with no Credential whose body takes more than 30 seconds, and any request that takes more than ten minutes, a staged upload excepted. Past 256 requests at once it answers busy, where it used to take on as many as arrived, and it reads at most 64 strangers' bodies at once, apart from everyone else's requests, so slow strangers hold up only other strangers. Before, a stranger could hold connections open for as long as they liked. [#368]
- A PDF is read in a program of its own, stopped once it takes more than 512 MB of memory or 10 seconds, and the file is refused saying which. Kamosu reads two at a time and answers busy past that. Before, a small PDF built to swell its reader could grow Kamosu by gigabytes, or keep it reading for as long as it liked. [#373]
- Reading a PDF, decoding a photograph and drawing a share card's picture no longer slow everyone else's requests while they run. [#373]
- A Crouton export stops being read once it has unpacked 4 GB, and the Import Report lists each recipe after that as not read. Before, a small zip could make Kamosu unpack far more. [#373]
- Kamosu forgets a name's wrong passwords an hour after the last one, so made-up names tried at the sign-in page are no longer kept for good. A name that had wrong passwords in the last hour waits as before. [#373]
- Building Meaning Search's index reads a recipe's long lines apart from its short ones. Before, a recipe with a long Note held hundreds of megabytes more while it was read, enough for a container with a memory limit to be killed partway through, and killed again on the same recipe every time it started. When a build starts again on the recipe the last one died on, the log now says so. [#389]
- Signing out first sends what the device wrote offline, such as a cooking moved on or a shopping-list tick. If some still cannot go, Kamosu says how many changes have not arrived and offers to wait and try again before signing out anyway. Before, they were thrown away without a word the next time anyone signed in on the device. [#380]
- In an English recipe, `1,020 g` is read as 1020 g, in an Ingredient Line and in a Step alike, and the shopping list and scaling use that. Before, every comma between digits was read as a decimal point, so it came out as 1.02 g. Saying a recipe is English reads its lines that way at once. `1,5 g` still reads as 1.5 g, and a French or Spanish recipe's comma is still its decimal point. [#383] [#397]
- A word too long for its line, such as a web address in a recipe's note, a Step or an Ingredient Line, wraps onto the next line where it reaches the edge. Before, it ran off the side of a phone and the page scrolled sideways. [#385]
- With Meaning Search on, a recipe that holds only a title no longer keeps the index catching up forever. Before, Settings said such recipes had changed since the last index for as long as they stayed that way, `meaning_search_status` counted them in `recipes_not_yet_indexed`, and the log said `index caught up` every minute with nothing changed. `build_meaning_index` now counts in `indexed` only the recipes and cooking notes it put in the index. [#391]
- The published agent files the recipe it reads under each of the Cookbook's Tags that plainly fits, and leaves the Tags a person put on where they are. Before, it was only told it could, and seldom did. [#436]
- A step links the ingredients it adds more often. *Add the chicken* links the chicken thighs, though the recipe is called *Honey lemon garlic chicken*, while *ladle the curry* in a beef curry still links no curry powder. *The garlic* means the garlic cloves rather than the garlic powder, a line with the same name in two sections is taken from the section the step works in, and *all the spice blend ingredients* links every line of that section. *The sauce*, *the mixture* or *the glaze* no longer links the soy sauce, and nor does what a step is *for*, as in *reserving a tablespoon for the rice*, or what it waits on, as in *when the rice is ready*. *Tomato* now finds *Tomatoes*. Before, a step in a later section took the first section's line, and a word shared by two lines linked both. [#439]

## v0.3.0 - 2026-10-18

### Added

- An Operator signed in directly can mint a Runner Key, for a Runner: a program beside Kamosu that will have an agent read what Kamosu cannot. Kamosu shows its Secret once. It acts as nobody, and can ask for work, keep hold of the Job it is working, report on it and nothing else. Both doors gain `mint_runner_key`, `list_runner_keys` and `revoke_runner_key` for an Operator, `runner_status`, which tells anyone signed in whether the instance has a Runner and when one was last heard from, asking for work or keeping hold of a Job, and `ask_for_work`, which answers a Runner Key alone. [#260] [#266] [#277]
- The Operator screen's Instance tab has a Runner section. It says what a Runner is and how long ago one last asked for work, or that none ever has, and lists each Runner Key by name and last use. An Operator makes a Runner Key there and sees its Secret once, and revokes one after a question saying what it stops. Until now this took `mint_runner_key` at either door. [#275]
- While a Runner Key stands, a link Kamosu cannot read is kept for an agent: a page with no recipe data, or one that refused Kamosu's fetch, lands as a bare recipe and a Job waits on it. Before, the first landed bare with no Job and the second landed nothing. A Runner takes the oldest waiting Job with `ask_for_work`, which names the link and the recipe, and the Job reads as running while that Runner holds it. The hold lasts two minutes, and the Runner keeps it by calling `renew_hold` in time, every 40 seconds as the answer tells it. A Job whose Runner went quiet reads as waiting again, and the next Runner that asks is handed it. The Runner that lost it is refused when it renews or reports, and told its hold is gone. The Job is read with `get_job`, or through the tasks extension at the MCP door, by the Person who asked and by the Co-authors of the Cookbook its recipe is in. Anyone else is answered as if the Job were not there, someone who sees the recipe through a Kitchen included. Kamosu's own Jobs read as before. Both doors gain `get_recipe_job`, which names the Job that waits or is being worked on a recipe to those same people, and answers `null` once it has ended and to anyone else who sees the recipe. The Person who asked can cancel the Job with `cancel_job`, or through the tasks extension at the MCP door, while it waits and while it is being worked, which Kamosu's own Jobs allow only while they wait. Nobody else can, a Co-author who reads it included. A cancelled Job reads as cancelled at once and keeps what the agent had saved. The Runner holding it is refused its next `renew_hold`, and told the Job was cancelled. A Runner holds one Job at a time. `ask_for_work` takes a mark in `ask`, which the Runner makes up for each new ask and sends again when a reply never arrived, so asking is safe to repeat. The Runner says how the Job ended with `report_on_job`: completed, failed, or could not be read, with the agent's own report. A Job reported failed waits to be tried again with what the agent had saved, as one whose Runner went quiet does. The third time a Job is taken and does not finish, it ends as failed and says it was tried three times. A Job the agent says could not be read ends at once, with the agent's reason. A waiting Job is handed to nobody while the Person who asked is disabled, and ends as failed if they are deleted. Revoking a Runner Key sends the Job it holds back to waiting. The agent writes the recipe meanwhile, with the Job Key below, and however many times it saves, the Job leaves one new Version after the bare one. The Import Report and `list_imports` name the Job in a new field, `agent_jobs`, with its state now. Once the Job has completed, the Report says an agent made the recipe, what the agent left undone, what it was unsure of, likely duplicates and the Foods left unused. A Job that failed is listed under what could not be read, with the reason, and its bare recipe is still listed as arrived. The same link handed over again while its Job waits or is being worked answers that Job. Once an agent has read it, the link matches the recipe the agent wrote: Kamosu's own bare reading of the page is not offered as a change, and no Job is made. After a Job that failed, the link makes a new Job on the same recipe. [#261] [#262] [#266] [#267] [#268] [#271]
- `ask_for_work` hands the Runner a Job Key with the Job, in a new field, `job_key`. It is a new kind of Credential, for the agent that does the Job. It acts as the Person who asked for the Job. It reads recipes with the Reading of each Ingredient Line, their Threads, search, Tags and Foods, as that Person sees them: `get_recipe`, `get_thread`, `branch_point`, `divergence`, `changed_since`, `search_recipes`, `list_tags`, `list_foods` and `get_food`. It writes the one recipe the Job is for, under that Person's Hand, and nothing on the recipe says an agent wrote it: `save_recipe_version` and `edit_recipe` write it, `create_recipe` creates it where the Job has none yet (below), `set_reading` corrects a Reading, and `set_recipe_tag` puts on a Tag the Cookbook already has. However many times the agent saves, its Job leaves one new Version in the recipe's History. Its saves fold into that one however far apart and never into the Version that was there before, so the bare recipe an Import landed stays as a Version of its own. A person's later save starts a new Version, even within the hour. If someone saves the recipe between two of the agent's saves, or a Copy, a variation, a Translation or a Bundle sent from the recipe holds the Version the agent is still shaping, the agent's next save is refused and the Job fails with that reason. Its save names no `translates_version_id`, and it corrects no Reading while another recipe reads word for word the same, since the two share their Readings. Aimed at any other recipe, each of those answers as if the recipe were not there. `upload_photograph` and `POST /api/photographs` store a Photograph for it. Every other Operation, and every other address outside the Operations, answers a Job Key as if it were not there, and the MCP door lists it those fifteen tools alone. A Job never starts a Copy: where a change by the Person who asked would start one in their own Cookbook, as it does once they have left the Cookbook that holds the recipe, the write is refused and the Job fails with that reason. A Job that fails keeps what it had saved. Kamosu shows a Job Key once and keeps only its hash. It stops working when the Job ends, a cancel included, and when the Person who asked is disabled or deleted. Each Runner that takes the Job is handed a Job Key of its own. The one from a hold that lapsed goes on working until the Job ends, and a save with it shapes the same one Version. Revoking a Runner Key ends the Job Keys it was handed. A Runner that repeats an ask gets a new Job Key in place of the one in the reply it lost. [#263] [#264] [#265] [#266] [#267]
- While a Runner Key stands, both doors take pasted text, a PDF or a picture for an agent to read, with `import_by_agent`. A scanned PDF is taken too. Until now a scan or a picture was refused, and pasted text or a PDF could only be split into a draft to sort by hand, which `read_pasted_recipe` and `read_recipe_pdf` still do. It answers the id of a Job that waits for a Runner, and no recipe exists until the agent creates one with `create_recipe`, in the asker's own Cookbook and under their Hand. A Job Key creates one recipe for its Job, and only for a Job that has none. A file that is none of the three is refused in words, and so is the whole Import on an instance with no Runner. What was handed over is kept as the Job's Original, beside the database and outside it: no Backup holds it, and no Bundle or Share Link carries it. A picture is remade first, which takes out where it was taken. The Runner is told where to fetch the Original, at `GET /api/originals/<job_id>`, and only that Job's Job Key fetches it. An Original is deleted 30 days after its Job ended, whether it completed, failed or was cancelled, and never while the Job waits or is being worked. The Job still reads afterwards, and its Import Report says so in a new field, `original_gone`, and still names what kind of thing was handed over. The Job's result is its Import Report, which lists the recipe once the agent has created it, says an agent made it, and names the reason when it could not be read. `list_imports` lists the arrival under `pasted_text`, `pdf` or `picture`. The same PDF or picture handed over again is known by its contents. While the first Job on it waits or is being worked, the answer is that Job, and once the agent has created the recipe, the answer is that recipe, as `branch_id` and `title`, with no Job. Pasted text is never matched. `ask_for_work` gains a field, `original`. On such a Job its `link` is null, and so is its `branch_id` until the agent has created the recipe. [#269] [#270] [#271]
- While a Runner Key stands, a Co-author can ask for an agent to read a recipe again, with `read_recipe_again`. An instance with no Runner is refused in words, and so is a recipe that came from no file and whose Source holds no http or https link on the internet. `can_read_recipe_again` says beforehand whether a recipe can be read again, from its link or from what was handed over, and if not, why. - Kamosu runs as a Runner with `kamosu runner --kamosu <address> -- <agent command>`, beside an agent of the Operator's choosing. It reads its Runner Key from `KAMOSU_RUNNER_KEY`, asks that one address for work every 10 seconds, and follows no redirect. An address holding a name or a password is refused, since the agent is handed it. It listens on no port and opens no database. The Runner Key is in no file of that folder and not in the command's environment, and the Runner blanks it in its own, where another program of the same user could read it. It reads a recipe's own words, then the cook's written recipe, then the video's frames and every caption over them, and gives a recipe from a video a photograph of each step and of the finished dish. It writes one recipe under that recipe's own name, never a page's headline, and from a source holding several it takes the first and names the others in its report. It copies a number the source gets plainly wrong and says so rather than correcting it, keeps a cook's correction when it reads a recipe again, reads a page that refuses it from the Wayback Machine's copy of that same page and never from another cook's recipe, and ignores orders a page gives an agent. ### Changed

- The filters on Recipes are three headed lines of chips: Cookbooks, Kitchens and Tags. A tap holds a chip and a second tap lets it go, so the All chip is gone. "My recipes" is now a tick beside the count, "Cooked or written by me". [#231]
- On a recipe, Cook this stands alone under the servings. The other acts are a grid of small buttons at the foot of the page, and a button is filled once its act has happened: the recipe is on the shopping list, or its Sheet is ready to share. [#220]
- Settings is a menu and four pages: Account, This device, Kitchens and cookbooks, This instance. On the phone it opens from a gear in the header, the header scrolls away with the page, and the tab bar is indigo where it was paper. [#218] [#221]
- A phone turned sideways cooks in two columns, the amounts beside the Step. On every size the switch that keeps the screen awake and "Not really cooking" sit under one ⋯, and the chip saying how much you are making wraps where it was cut short. [#222]
- A Cover is drawn from sixteen pasta shapes where there were eight, so about half the recipes with no photograph change shape once. [#228]
- Words that acted when tapped are now drawn as buttons, and small labels are a size larger. In the editor the tools under each Ingredient Line are small marks beside it. A control reached with the keyboard wears a clear outline where it had the browser's blue ring. [#225]
- Dates are written the same way on every screen, in the interface's language, and every page has a title of its own in the browser tab. A count of one reads "1 recipe", and a tablet is no longer called a phone. [#224]
- The pages read before signing in draw no tab bar and no gear, and the card offering to install Kamosu waits until somebody is signed in. A signed-in person who opens a Cookbook Invite keeps their navigation. [#214] [#226]
- Enter saves a Food's names, a Food's cup weight, a line's Reading and the public address, each of which needed its button before. [#203]
- The source moved to `github.com/BatterWorks/Kamosu`. The old address redirects, and the image is still `battermanz/kamosu`. [#237]

### Fixed

- A line with the amount after the Food is read: "Oignon jaune : 2", "Eau : 800 ml" and "Pâtes orzo 200 g" each used to be stored whole as a Food with no amount. [#207]
- An amount written against its Unit is read, as in "100g Crème". `cs` and `c.s.` are tablespoons, `cc` and `c.c.` teaspoons, `pince` is a pinch, and after an amount a lone `t` is a teaspoon and a lone `T` a tablespoon. "Un peu de", "a little", "a bit of" and "un poco de" opening a line are dropped from the Food's name. [#208]
- French "thé", "dés" and "dé" are words of a Food's name. They were dropped as "the", "des" and "de", so "1 thé vert" named the Food "vert". The Quebec teaspoon, "cuillère à thé", still reads as a teaspoon. [#213]
- An accent typed as its own character stays on a Food's name, so one name typed on two keyboards is one Food. [#230]
- A Step links an ingredient only by the main word of its name. "Add the chicken" no longer shows the chicken broth, and "steamed rice" no longer shows the rice vinegar. A Step saying "le thé" now links the tea. [#212] [#230]
- A cooking kept as a Version shows, with its rating, under that Version in the History. It used to sit under the Version the cooking started from, and the Version that was eaten looked untried. `get_thread` answers `eaten_version_id` on every Attempt. [#209]
- A recipe on the phone's shopping list shows its whole title on one row. The title was squeezed beside "shopping for 4 servings" and wrapped to four lines. [#226]
- The library Kamosu makes its outgoing HTTPS connections with, to fetch a web page to import or the Meaning Search model, is past a published flaw in how it checked the TLS handshake (RUSTSEC-2026-0285). [#244]

## v0.1.0 - 2026-09-28

The first release. Kamosu has been cooked from in one household since August
2026. This is the first time anyone else can run it: it is now
public, licensed under the AGPL-3.0, and published as a ready-made image,
`battermanz/kamosu`, for both amd64 and arm64.

Nothing is listed here as added or fixed, since there was no earlier release to
compare with. What 0.1.0 contains:

- **Recipes that keep their history.** Every save is a new Version and none is
  ever lost. Variations and Translations are Branches of the same recipe, and
  the History screen shows where two of them parted and every line that
  differs.
- **Cooking mode.** Step by step, with the amounts each step uses, ticked
  ingredients, timers read out of the step text, and the recipe scaled to what
  you are making. It works offline, and a cooking started on the phone carries
  on on a tablet.
- **Attempts.** A diary of each cooking, with a rating, photos, notes and what
  was actually done, any of which can be promoted into the recipe.
- **Ingredient lines kept as written**, read into amount, unit and food for
  scaling, metric and US conversions, oven temperatures and the shopping list.
- **A shopping list** worked out from the recipes you picked, merging the same
  food across recipes, plus loose items you type.
- **Imports** from a web page's schema.org data, a pasted recipe, a recipe PDF,
  a Crouton export, and another Kamosu's recipe files and Share Links.
- **Sharing.** A Share Link per recipe for anyone who holds it, a printable PDF
  Sheet, and a recipe file carrying the full history.
- **People.** Invites instead of signup, a Cookbook per person that two people
  can join, Kitchens for cooking from each other's Cookbooks, and Operators who
  run the instance without being able to read anyone's recipes through the app.
- **Agents.** Every operation is offered over MCP at `/mcp` exactly as the web
  app gets it, with per-person Access Keys that can be read-only.
- **Search** by words from the start, and by meaning once an Operator turns on
  the optional EmbeddingGemma model, which Kamosu does not ship.
- **Backups** taken automatically, three kept (a day, a week and a month back),
  and a Snapshot before every upgrade migrates the database.
- **English, French and Spanish**, for the interface and for recipes.

The things Kamosu does not defend against are listed in
[SECURITY.md](SECURITY.md).
