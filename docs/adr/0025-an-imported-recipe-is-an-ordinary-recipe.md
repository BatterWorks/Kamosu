# An imported recipe is an ordinary recipe

**Import** brings recipes in from a Crouton `.crumb`, a web page or a **Bundle**. What comes out the other side is a recipe like any other: nothing about where it came from is stapled to it, and nothing marks it as second-hand.

_(Amended by [ADR 0041](./0041-a-recipe-is-written-in-a-cookbook-and-seen-in-a-kitchen.md): an Import lands in the asker's **Cookbook**; the Home Kitchen is retired, and so is the question of letting an Import choose where it goes. The import ledger below matches within a Cookbook, not a Kitchen.)_

> **An import leaves nothing on the recipe. What it remembers, it remembers itself.**

- **An Import keeps a ledger** of what it made — the foreign id it read (a Crouton UUID, a URL) against the **Lineage** it became. Held by the import, never on the recipe.
- **Re-importing matches through that ledger.** Recipes it has seen are matched, not shelved again; changed ones are **offered** as candidates to tick, never written over silently.
- **No mark on a rebuilt line.** Crouton did not keep the sentence, so Kamosu assembles one and that is the truth from then on.
- **Nutrition arrives only where the source gave a number.** Crouton's `neutritionalInfo` blob is dropped; a web page's structured data fills the field.
- **A Passenger gets a card**, like any recipe a **Component** of your own points at.
- **The report is the ledger read by a person** — what arrived, what needs a tap, what could not be read.
- **The Hand on an imported Version is the importing Person's**, and **Source** carries where it really came from.

## Why

- **A foreign id is a fact about a migration, not about the dish.** This is [ADR 0023](./0023-a-sheet-carries-the-recipe-not-the-library.md)'s cut — what is a fact about the dish is on the page, what is a fact about how Kamosu files the dish is not — applied one layer down. Keeping the Crouton UUID in the ledger rather than on the **Branch** means it never enters a **Version**'s fingerprint, never travels in a **Bundle**, and can be deleted entire the day Crouton is gone, without touching a recipe. On the Branch it would have been permanent, worldwide, and load-bearing for a need that lasts a fortnight.
- **Migration is not a single act, and a model that assumes it is makes you afraid to redo it.** The library will be imported, inspected, and imported again — while Crouton is still on the phone, since [ADR 0009](./0009-the-v1-cut-line-is-drawn-at-shape-not-at-features.md) draws done at *the day Crouton is deleted*. Without memory, the second run doubles the library and the third triples it, and the rational response is to never re-run, which is exactly backwards during the one week the importer matters.
- **One rule covers both importers.** A web link's foreign id is its URL, so re-fetching a page updates the recipe already held instead of shelving a second copy. Nothing was built twice.
- **A rebuilt line is not wrong, and marking it would fire on 72% of the library.** 624 of the 863 real ingredient rows carry a quantity, so 624 get assembled from `"cloves minced garlic"` plus `{2, ITEM}`. The vast majority read correctly; the handful that do not — `", boneless, skinless chicken breasts, trimmed"` — are obvious at a glance and get fixed when seen. A mark on two-thirds of every page is the trap [ADR 0015](./0015-a-name-is-not-identification-it-is-a-reminder.md), [ADR 0016](./0016-kamosu-converts-to-the-kitchen-not-to-the-arithmetic.md) and [ADR 0018](./0018-a-share-begins-at-the-beginning-and-there-is-no-unsay.md) each refused in turn, arriving a fourth time: a mark that fires always says nothing.
- **And [ADR 0002](./0002-the-written-ingredient-line-is-the-truth.md) is not being broken, which is why it needs no apology.** That ADR governs what Kamosu does with a line it holds — preserve it, show it, let a person edit it. There was no written line inside the `.crumb` to preserve. Kamosu writes one and then keeps the promise about it forever after. `crouton-real-export.md` recommends marking it as reconstructed; that was a reader's instinct about a lossy format, not a decision about Kamosu, and it is declined here on purpose.
- **A wrong ingredient line is caught and a wrong number never is.** That asymmetry decides nutrition. `neutritionalInfo` on 25 recipes is unparsed scrape debris — units drifting between `g` and `grams`, the schema.org `@context` key leaking straight through, and one entry two nutrition panels concatenated with no labels. Parsing `610 Calories / 67g Carbs / 16g Fat / 210 Calories` yields something plausible and false, sitting in a numeric field where nobody will ever look at it hard enough to doubt it. [#4](https://github.com/BatterWorks/Kamosu/issues/4) found the half-measure Crouton took gives you neither honesty nor data; declining to guess is the whole distance from it.
- **"Passenger" describes how a recipe rode in the zip, not what it is.** The word stops applying the moment the zip is open. Giving one no card would mean inventing a second class of recipe — present but unlisted — that nothing else in Kamosu has, and it would make Marc's dough behave differently from the dough your own pizza points at under [ADR 0008](./0008-a-composed-recipe-is-an-ingredient.md), for no reason a cook could name. It would also strand the dough permanently the day the pizza's line is edited away.
- **[ADR 0020](./0020-a-bundle-is-one-recipes-worth-of-vault.md) built subject-naming for this.** The sidecar names which Lineages a Bundle is *about* so the import screen can say *"Pizza, and one component it needs"* rather than *"2 recipes"*. That sentence only has work to do if two recipes are actually arriving.
- **Almost nothing half-works, so the report is not an error log.** A `.crumb` parses or it does not; if it parses there is a recipe, however thin, because [#6](https://github.com/BatterWorks/Kamosu/issues/6) requires only a title. The 4 recipes with no ingredients and the 6 with no steps imported *correctly* — a bare name and a link is a real recipe and a real habit, two of the 86 being 280-byte stubs. Reporting them as failures would teach distrust of a migration that went fine.
- **An importer is even less a Person than an agent is.** [ADR 0007](./0007-a-recipe-is-held-by-a-kitchen-not-a-person.md) already settled that an agent is never an account and acts under the **Hand** of the Person who set it going; a parser has still less claim. Minting a Kamosu-the-machine Hand would put a non-Person into a model that has none, to express something [ADR 0015](./0015-a-name-is-not-identification-it-is-a-reminder.md) already routes through **Source**: credit is written down, never wired up.

## Considered options

- **Every import is new** — 86 recipes becoming 172. Rejected: makes re-importing frightening during the one period it is needed.
- **The foreign id on the Branch.** Rejected: permanent stored shape, travelling worldwide in every Bundle, for a fortnight's need.
- **Matching and overwriting automatically.** Rejected: a machine re-reading a stale file silently replacing what you typed. Offering it is [ADR 0022](./0022-doubt-makes-a-new-food-never-a-merge.md)'s timidity and [#15](https://github.com/BatterWorks/Kamosu/issues/15)'s tick-box, both already chosen.
- **Marking a rebuilt Ingredient Line**, per line or per recipe, travelling or not. Rejected: see above. All three of the ticket's questions about the mark — what it looks like, whether it un-marks, whether it travels — stopped existing rather than being answered, as two of [#23](https://github.com/BatterWorks/Kamosu/issues/23)'s five did.
- **Best-effort parsing of `neutritionalInfo`.** Rejected on the visible/invisible asymmetry.
- **Keeping the blob in the recipe's Note.** Rejected: a **Note** is about the dish as written, not a place to park scrape debris on 25 recipes.
- **A Passenger sitting quiet until pointed at**, or offered as a tick-box at the door. Rejected: a second class of recipe, and a question at a moment that should not ask one.
- **Joining the three `-1` pairs into one Lineage.** Rejected, and firmly: they carry different Crouton UUIDs, and [ADR 0004](./0004-one-lineage-many-branches.md) forbids ever joining two Lineages, so a guess at the door would be permanent and unfixable. They share a source link, so they surface as **Related Recipe** candidates under [ADR 0008](./0008-a-composed-recipe-is-an-ingredient.md) — the rule doing the job it was written for.

## Consequences

- **The ledger matches within a Kitchen.** [ADR 0007](./0007-a-recipe-is-held-by-a-kitchen-not-a-person.md) already forbids reaching into another Kitchen's recipes to change them, so a re-import cannot offer to overwrite a recipe it does not hold.
- **The ledger is in a Backup and in no Bundle.** It is instance-local bookkeeping, like the Access Key that wrote a Version.
- **It is droppable.** When Crouton is gone the whole ledger can be deleted and every recipe is untouched — the payoff for keeping it off the Branch.
- **A Crouton library imports as unrelated recipes.** No **Lineage** is joined, no Branch is inferred, no **Component** is guessed at ([#15](https://github.com/BatterWorks/Kamosu/issues/15)). Your hand-made versioning stays hand-made until you say otherwise.
- **Parity costs nothing.** *Import this file*, *how did the import go?* are ordinary Operations under [ADR 0001](./0001-both-doors-generated-from-one-operation-catalogue.md), so the agent door gets the report without a second thing being built.
- **A damaged Bundle is reported in the same voice as everything else** — history refused, words kept as a new recipe, no Lineage id, all three said plainly ([ADR 0020](./0020-a-bundle-is-one-recipes-worth-of-vault.md)) — rather than in a dialog of its own.
- **Mechanics the 86-recipe corpus dictated, recorded so they are not rediscovered:** import by UUID and never by filename; decode HTML entities Crouton scraped and never unescaped; `quantityType: SECTION` is a control row and both of Crouton's two section fakes land on a real **Section**; the Crouton unit enum maps as [#21](https://github.com/BatterWorks/Kamosu/issues/21) set out, cups and spoons as US measures; `sourceImage` is the source site's favicon and is dropped ([ADR 0017](./0017-a-photograph-is-known-by-its-contents.md)); `defaultScale` is dropped, there being no stored scaling factor anywhere in Kamosu by the deliberate choice of [ADR 0008](./0008-a-composed-recipe-is-an-ingredient.md) and [ADR 0010](./0010-a-cook-in-progress-is-an-unfinished-attempt.md); **Language** is detected per recipe and set, since there is none to disagree with ([ADR 0006](./0006-a-translation-is-a-branch.md)); the import lands in the **Home Kitchen** ([ADR 0007](./0007-a-recipe-is-held-by-a-kitchen-not-a-person.md)).
- **A Crouton tag lands in the Kitchen's own tag list** (added 2026-09-23, [#128](https://github.com/BatterWorks/Kamosu/issues/128)): the first export to carry tags arrived a month after the corpus above, which had none. A tag comes in by its name as an English word, whatever the recipe's **Language**, since Crouton says nothing of one and the words are English; its colour is dropped, Kamosu **Tags** having none; and a re-import only ever adds, so tagging done in Kamosu is never undone. This is the rule a **Bundle**'s tags already follow, and a Tag is outside the fingerprint ([ADR 0035](./0035-a-tag-is-how-a-kitchen-files-not-what-a-recipe-is.md)), so filing moves no Version id.
- **A failed web fetch still makes the recipe** — its title and its link, nothing else. Refusing would be Kamosu declining to store what two of the 86 real recipes already are.
