# A phone shares into Kamosu through one Operation and an Add-only key

_(Amended by [ADR 0057](./0057-a-languages-words-are-data-and-its-grammar-is-code.md), #495: the count of Languages `add_this` answers in follows what a Person can read Kamosu in.)_

A cook on a phone can add a recipe from the phone's own Share menu. They share a web page, an Instagram or TikTok post, one or several photos, copied text or a PDF, tap "Add to Kamosu", and a short message says it was sent. On an iPhone the way in is an Apple Shortcut that Kamosu publishes. On Android it is Kamosu itself, installed from Chrome. Both hand what was shared to one new Operation, `add_this`, and show the message it answers with. Settled on 2026-10-24 in a design session (#452). How other recipe apps do it is in `docs/research/sharing-a-recipe-in-from-a-phone.md`. This amends [ADR 0048](./0048-an-agent-beside-kamosu-reads-what-kamosu-cannot.md), whose Original is one file, and [ADR 0044](./0044-wide-screens-are-the-same-app-laid-out-by-room-and-designed-by-role.md), whose Recipes refuses more than one file.

Until now a recipe found on a phone had to be carried into Kamosu by hand: open Kamosu, find the add box, paste. That works for whoever set Kamosu up and loses everyone else in the household, which is the person this is for.

## What was decided

- **An iPhone shares through a Shortcut, and Kamosu ships it.** iOS lists no web app in its Share menu (WebKit has never shipped Web Share Target), so the self-hosted recipe apps that offer an iPhone way in at all, without an app of their own, offer a Shortcut. The maintainer builds Kamosu's once on an iPhone and publishes its iCloud link. The repository keeps a written list of its steps, so it can be built again if the link is ever lost, and Kamosu's Settings links to it.
- **The Shortcut holds as little as it can.** It sends what it was given to `add_this` and shows the message `add_this` answers with. Kamosu decides everything else. It chooses whether a link goes to Kamosu's own reader or to the agent, says what is true on an instance with no agent, and words the message in the asker's Reading Language. The Shortcut sends its own version number with every call, so Kamosu can say when a newer one is available, and an older one keeps working for as long as Kamosu can still serve it.
- **From Safari, the Shortcut sends the link and not the page.** Kamosu fetches the page itself, as it does from the browser. Where it cannot, because a site refuses it or the page is behind the cook's own login, the cook is told to copy the recipe's text and share that.
- **It answers quickly, and waits only for a link's page.** For text, pictures and a PDF, `add_this` starts the import and answers at once with a message, never with the finished recipe, which arrives on the shelf when the agent has read it. For a link it waits for Kamosu to fetch and read the page, for about 10 seconds at most, because only then does it know what to say: the recipe's title, that the agent is reading it, or that the page could not be opened. When the wait runs out, as it can behind a large import, it says the link was sent. An import that fails later shows on the Imports screen, as any import does.
- **The Shortcut carries an Add-only key.** An **Add-only key** is a third kind of Access Key, beside the read-only key and the Operator key, chosen when it is minted. It may call `add_this`, stage the files `add_this` takes at `POST /api/uploads`, and read a Job as its Person may. Nothing else. Each declaration in the Catalogue says whether an Add-only key may call it, and `Core::execute` enforces that, as it does for a Job Key. The routes outside the Catalogue (Photographs, Bundles, Sheets, Originals) refuse it in the Core's own check of the Credential, and the MCP Door lists it only what it may call.
- **Setup is one paste.** A Settings screen mints the Add-only key and shows a single setup code, once, holding both the instance's address and the key. The Shortcut asks for that code when it is installed and splits it itself.
- **Several photos shared together are the pages of one recipe.** An import now takes several pictures, and its Original is that set in order. The agent reads them as one recipe. The add place on Recipes takes several pictures at once too, where ADR 0044 refused more than one file.
- **Everything to the agent, or only what Kamosu cannot read.** The setup screen asks which one, and keeps the answer with the Add-only key. A link to a page with recipe data then goes to the agent too, if the cook chose that. It can be changed later in Kamosu, and the Shortcut never needs reinstalling for it.
- **The same link is not added twice.** `add_this` knows a link that a recipe the cook can see already came from, and answers with that recipe's title instead of starting another import. A link one of the cook's own imports is still reading is answered the same way. Pictures and PDFs were already known by their contents.
- **Android shares into Kamosu itself.** The installed web app declares a share target, so Kamosu is listed in Android's Share menu with no Shortcut and no key, signed in as the browser already is. It calls the same `add_this`.
- **It is offered on every instance.** Without a Runner, a link to a page with recipe data is added in full. A page without it is not added from the phone: the message says to open Kamosu and add the link there, where its text can be checked before it is saved. Text, pictures and PDFs are refused with a message saying this Kamosu has no agent to read them. Where a Runner exists but none has asked for work lately, the message says the agent is not answering and will read it when it is back.
- **Defaults taken in the session.** The recipe lands in the cook's own Cookbook, as every import does. A Demo does not offer the setup screen, since it refuses imports. The agent question is not asked on an instance with no Runner. Text that is only a link is that link. Android keeps the agent choice with that phone's Session. The browser's own add box is unchanged and does not refuse a link already on a shelf.

## Why

- **Shipping the Shortcut, not documenting how to build one.** A Shortcut each person builds from instructions is beyond the people this is for. The prior art shows the cost of leaving it to others. Mealie's Shortcut was written by a user outside the project and broke twice when Mealie's addresses changed, and Norish's, which its maintainer posted in an issue, broke once the same way.
- **One Operation, so the Shortcut stays dumb.** The Shortcut is the one piece of Kamosu on someone else's phone that a release cannot update. Every rule written into it is frozen until that person reinstalls it, which most never do. A rule in `add_this` improves with every release, and an agent at the MCP Door gets the same "add this, whatever it is".
- **An Add-only key, not an ordinary one.** The Shortcut keeps its key in plain view in the Shortcuts editor, and the key goes along if the Shortcut is shared from that phone. An ordinary key acts with the whole of its Person's reach, and in Kamosu that includes deleting a recipe for good. [ADR 0031](./0031-a-secret-is-spent-or-revoked-never-on-a-clock.md) answers a leaked key by visibility rather than restriction, because scoping a key to one Kitchen would be a wall at every Operation. A key kind with a short list of what it may call is no such wall. It is decided once per declaration, as the Job Key is. A leaked Add-only key can only add recipes, which a cook can see and delete.
- **The link only, because a pop-up costs more than it buys.** Sending the page from Safari needs a setting buried in iOS and a permission prompt the first time the Shortcut meets each website. That lands on the person the one tap was for. What it would have reached, paid and bot-blocking sites, still has a way in through copied text.
- **Several pictures, not one stitched picture.** Mealie stitches photos into one image because a Shortcut sends one file per field, and its docs admit the text is read less well. A model shrinks a picture before reading it, so three phone photos in one strip lose the small print of a cookbook page. The cost is Kamosu's own, and it closes a gap the browser already had.
- **Offered everywhere.** Most instances have no Runner. Links are what a phone shares most, and a page with recipe data needs no agent.

## Considered options

- **Opening Kamosu's page in Safari with the link in the address**, as Recipe Filer recommends, with no key at all. Rejected: a picture or a PDF does not fit in an address, and Safari's sign-in is separate from the Home Screen app's.
- **A Shortcut that calls today's Operations one after another.** Rejected above: every rule in it is frozen on strangers' phones.
- **An ordinary Access Key in the Shortcut.** Rejected above.
- **Two published Shortcuts, one always using the agent.** Rejected: two links and two step lists to keep, and changing one's mind means reinstalling.
- **Waiting in the Shortcut until the recipe is read**, then offering to open it. Rejected: a read can take minutes, and iOS may stop a Shortcut that is left.
- **Always answering "sent" for a link**, with the Imports screen showing the links that went wrong. Rejected: a failed link would fail silently on the phone, and fetching a page is usually well under a second.
- **A clipboard fallback for Instagram**, run from the Home Screen. Not taken: Instagram's own Share button reaches the system Share menu through "Share to…", so the Shortcut is listed there.

## Consequences

- **The published Shortcut lives on the maintainer's iCloud account.** Apple publishes a Shortcut only from an Apple device, so it cannot be built from the repository. The step list is the way back if the link is lost, and a release that changes the Shortcut changes the link Kamosu shows.
- **`add_this` is a contract with phones Kamosu cannot reach.** What it takes and answers changes only in ways an older Shortcut survives, and the version number is how Kamosu says when one has to be replaced.
- **An Original can be several files.** Reading again and sending again handle the set, and the agent fetches each one.
- **The server writes prose in the reader's language.** `add_this` words its answer in the asker's Reading Language, in every language a Person can read Kamosu in. A Sheet and the Share Link page also keep their words in Rust, but choose the recipe's Language, since their reader has told Kamosu nothing.
- **Android is tested through Chrome's Android emulation** until someone with an Android phone tries it.
